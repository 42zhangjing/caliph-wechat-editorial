# 群聊编辑工作流

## 一、素材范围

source JSON 来自 yichen `digest-source`，只代表已经存在于本地 vault 的消息。先确认：群名、起止日期、素材最后一条消息时间、是否包含图片/视频/语音转写。没有最新素材时说明缺口，不用旧数据冒充最新数据。

`prepare_source.py` 会保留 `time`、`sender`、`type`、`content`，并移除数据库名、表名、内部 user name 等字段。规范化素材包仍是敏感文件，只放在报告目录。

## 二、日报编排

日报通常选择 3—6 个节点：

1. 头条：当天最能代表群体气质或形成讨论链的事件。
2. 上午/下午/晚间：按话题转折，而不是机械按小时切段。
3. 人物节点：只有当某人推动了讨论、提供了资料或完成了产出时才入选。
4. 收束：一句真实金句、一个未解决的问题或一个自然的余韵。

推荐结构：

```text
报头 → 今日一句话 → 头条故事 → 2—5 个时间线节点
     → 群友角色卡 → 金句墙 → 数据收尾
```

## 三、周报编排

周报不要把七天日报简单拼接。先寻找变化：

- 本周反复出现的主题；
- 从玩笑变成认真讨论的问题；
- 某个工具、产品或观点如何在群里扩散；
- 哪些人承担了提问、查证、解释、吐槽、收束等角色；
- 本周留下的未决问题。

周报通常 4—7 个章节：本周头条、主题演化、人物群像、群内生产物、争议与分歧、下周悬念。除非有真实依据，不写“群体共识”“大家一致认为”。

## 四、引用和事实

- 原话只能来自 source JSON，引用尽量短，并附发送者和时间。
- 对链接和文件只陈述消息中明确可见的标题；没有打开或核验外链时，不把链接内容写成已证实事实。
- `[图片]`、`[视频]`、`[文件]` 是类型线索，不是内容本身。看不到媒体时，不描述其中的画面、人物或结论。
- 需要概括敏感、成人或私人话题时，写主题层面的编辑摘要，不复制露骨原文。
- 人物评价使用“本期表现出”“在这段讨论中承担了”这类限定语，不诊断人格、健康、家庭或身份属性。

## 五、视觉层级

优先建立三个层级：

1. 头条：最大标题、短副标题、一个明确的时间或主题标签。
2. 故事：两栏或三栏正文，穿插少量引语和人物标签。
3. 余韵：金句、数据、未决问题或编辑手记。

使用米白底、墨黑正文、单一朱砂红强调色和深蓝辅助色；减少装饰线和花纹。A3 印刷版必须按真实内容调节版数和密度，不能靠重复金句或空白占位填版。

## 六、交付前检查

- 事实、推断、原话有明确区分。
- 报告没有 key、salt、wxid、数据库路径或内部表名。
- 每个引用都能回到 source JSON。
- 每个故事节点都有主题，不是消息列表。
- 图片不可见时没有编造图说。
- HTML 能打开，中文字体有回退，标题没有孤字断行。
- PDF 若生成，页面尺寸为 A3，页数与 report JSON 的 pages 一致，且没有截断。
